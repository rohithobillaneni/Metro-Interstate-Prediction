# Reproduce local inference and API startup

The supported local API uses a newly trained bundle. It no longer reads
`/app/models/traffic_model.pkl` at import. Importing `src.app` is safe without a
model; starting the application requires an explicit bundle and a separately
trusted manifest digest. The historical models remain preserved and unsupported.

## Trust boundary

This milestone retains scikit-learn's existing pipeline and Python pickle.
**Pickle can execute code. A checksum does not make an untrusted model safe.**
Only use a bundle generated by your own reviewed local training command. Keep
its returned manifest SHA256 separately in trusted configuration. Do not obtain
both an arbitrary downloaded artifact and its supposed trusted digest from the
same untrusted supplier. There is no model-upload endpoint or automatic fallback.

At startup the loader verifies the supplied pin against bounded manifest bytes,
then checks the feature schema, Python major/minor, exact evaluation dependency
versions and prediction-source hashes. It verifies bounded model bytes against
the pinned manifest and deserializes that same buffer, without reopening a
pathname. Changed, missing, incompatible or incomplete bundles prevent startup.
These integrity checks do not sandbox Python or authenticate the training author.

## Train a fresh bundle

From the repository root, with Python 3.13:

```sh
python3.13 -m venv .venv
.venv/bin/python -m pip install --only-binary=:all: --require-hashes -r requirements-serving.txt
.venv/bin/python -m unittest discover -s tests -v
mkdir -p generated-models
.venv/bin/python -m src.artifacts --data data/Metro_Interstate_Traffic_Volume.csv --output generated-models/pre2017-v1
```

The final command prints a JSON object containing `manifest_sha256`. Copy the
value from **this local training run** into the configuration below. The output
directory must not exist; neither historical artifacts nor previous runs are
overwritten. A failed disk write may leave an incomplete directory; preserve it
for diagnosis and choose a new output path. No usable pin is returned for a
failed training command. Generated bundles are ignored by Git.

Training uses the same fixed forest, transformations and pre-2017 rows as the
[evaluation protocol](evaluation.md). Validation and reserved 2018 targets are
not used to fit the model. The manifest records dataset hash, row accounting,
training timestamps, model configuration, environment and source hashes. This
is a reproducible reference model, not a claim of operational forecasting value.

## Start and query

```sh
export METRO_MODEL_DIR=generated-models/pre2017-v1
export METRO_MODEL_MANIFEST_SHA256=PASTE_THE_DIGEST_FROM_YOUR_LOCAL_TRAINING_RUN
.venv/bin/python -m uvicorn src.app:app --host 127.0.0.1 --port 8000
```

In another terminal:

```sh
curl --fail-with-body http://127.0.0.1:8000/predict \
  -H 'Content-Type: application/json' \
  -d '{"temp":15,"clouds_all":50,"holiday":"No","weather_main":"Clouds","weekday":"Monday","hour":12,"month":"January"}'
```

The response is `{"prediction": <vehicles_per_hour>}`. Temperature is Celsius;
cloud percentage is 0–100, hour is an integer 0–23, weekday/month use full English
names, and holiday is `No` or `Yes`. Booleans, numeric strings, nonfinite numbers,
unknown fields and missing required fields are rejected. Weather is a nonempty
string of at most 64 characters after trimming; unseen weather labels use the
existing encoder's unknown-category handling. `hour_category` is optional and
derived from hour. For older clients that supply it, a contradictory value is
now a 422 error. Other valid historical request fields and the response key are
preserved. Invalid request responses do not echo raw input. Unexpected prediction
failures return a generic 500 message. Prediction runs outside the async event
loop through a synchronous route; this is not a throughput benchmark.

The frontend now derives its hour category and accepts `METRO_API_URL` (default
`http://127.0.0.1:8000/predict`) with a 10-second timeout. Frontend dependencies,
startup and container deployment remain separate follow-up work. The old Docker
images still use Python 3.9 and are **not supported by these local instructions**.
Do not run the old Docker walkthrough as a verified deployment recipe.

API tests use newly trained synthetic bundles, request-boundary failures and
concurrent requests. They never load the historical model files. HTTPX 0.28.1 is
currently accepted by Starlette's TestClient but emits a deprecation warning;
a future dependency update should verify its replacement before changing pins.
